# [UI-6] 화면 고침: 필터 갱신·터널 표시·토큰·아이콘·헤더 글자·안내 문구        커밋: 64ec83d..(이 문서 커밋)

## 한 줄 요약
UI 보고서에서 승인하신 고칠 것(결정 1·3·4·5·6·8·9)을 반영했습니다. 필터를 켜 두어도 목록이 1초 안에 갱신되고, 접속 토큰은 주소창에서 바로 지워집니다. 헤더의 한글·특수 문자는 제대로 풀어 보이고, 안내 문구는 실제로 필요한 설정을 알려 줍니다.

## 무엇이 달라졌나
| 전에는 | 이제는 |
|---|---|
| 필터를 켠 채 요청이 계속 오면 필터 결과가 멈춰 있었다(요청이 0.3초 넘게 끊겨야 갱신) | 요청이 계속 와도 **최대 1초 안에** 다시 받는다. 조회는 한 번에 하나만 하고, 조회하는 동안 필터를 바꾸면 옛 결과는 버린다 |
| 데이터가 오간 뒤 브라우저가 끊은 HTTPS 터널도 상세에 "실패 aborted"로 보였다 | 그런 터널은 "끝남 — 데이터가 오간 뒤 브라우저가 연결을 닫았습니다(원래 기록: aborted (client))". 목적지가 끊었거나 목적지에서 받은 것이 없으면 그대로 실패이고, 목록에도 "터널 실패"(빨강) |
| 토큰(`#t=…`)이 주소창에 계속 보였다 | 페이지가 열리자마자 주소에서 지우고 **이 탭의 메모리에만** 둔다. 새로고침하면 토큰이 사라지므로 터미널 주소를 다시 붙여 넣는다(사용자 결정 "메모리에만"). 같은 탭에 새 주소를 붙여 넣으면 새 토큰으로 다시 연다 |
| 열 때마다 콘솔에 `/favicon.ico` 404 | 작은 아이콘(`/favicon.svg`)을 보이고, `/favicon.ico`에는 빈 응답(204) |
| 헤더의 한글이 `í\u0095\u009c`처럼 깨져 보였다 | 바이트가 올바른 UTF-8이면 풀어 보이고 "(UTF-8로 풀어 보임 · 원래 바이트 ed 95 9c …)"를 붙인다. 숨은 방향 문자는 풀어도 `⟨U+202E⟩`로 보인다 |
| 다른 페이지의 링크로 들어오면 "프록시 우회 목록에 넣으세요"가 먼저 나왔다 | "터미널에 나온 대시보드 주소를 브라우저 주소창에 직접 붙여 넣어 여세요"가 먼저 |
| 프록시 거절 안내: "예외 목록에 127.0.0.1과 localhost를 넣으세요" | "Chrome·Edge는 원래 loopback을 프록시로 보내지 않습니다. 로컬 개발 서버까지 기록하려고 `<-loopback>`을 넣었다면 그 **뒤에** 대시보드 주소를: `<-loopback>;127.0.0.1:<포트>;localhost:<포트>`". 터미널 안내에는 실제 포트가 들어간다 |

## 왜 조심해야 했나 (검토 에이전트 사례 `docs/ai/ui6-cases.md`)
- **토큰을 어디에 숨기느냐**: 주소에서 지우면서 새로고침 때도 쓰려고 `history.state`나 `window.name`에 넣으면, 탭 복원·다른 사이트로 이동할 때 따라갑니다(K15). 그래서 메모리에만 둡니다.
- **그래도 막을 수 없는 것**: Chrome은 페이지가 주소를 지우기 **전에** 방문 기록·세션·아이콘 DB에 토큰이 든 주소를 이미 씁니다(K14·K24 — 이번 실측 E198에서도 History, Sessions, Tabs, Top Sites, Favicons에 남음). 토큰은 실행마다 바뀌므로 프로그램을 다시 켜면 쓸모없어지지만, 켜 둔 동안에는 프로필 폴더를 읽을 수 있는 프로그램이 볼 수 있습니다 → UI 마무리 보고에 올립니다.
- **글자를 다시 풀면 새로 보이는 글자**: 지금까지는 Node가 한 글자 = 한 바이트로 줘서 숨은 문자가 생길 수 없었는데, UTF-8로 풀면 태그 문자(ASCII를 몰래 실어 나름)·한글 채움 문자처럼 보이지 않는 글자가 생깁니다(K8). 그래서 숨은 문자 목록을 넓혔습니다. 단 이모지 표시 선택자(U+FE0F)는 ❤️ 같은 이모지마다 표시가 붙어서 넣지 않았습니다 → UI 마무리 보고에 올립니다.
- **잘못된 UTF-8**: 느슨하게 풀면 서로 다른 바이트가 모두 `�`가 되어 구별되지 않습니다(K11). 엄격하게 풀다가 실패하면 원래 표시 그대로 둡니다.
- **"끝남"의 범위**: "바이트가 있으면 정상"으로 하면 목적지가 중간에 끊은 경우도 정상처럼 보입니다(K31). 위·아래 모두 데이터가 오갔고 **브라우저**가 끊은 경우만 "끝남"이고, 그때도 "정상"이라는 말은 쓰지 않습니다(K33).
- **`<-loopback>` 안내 순서**: `<-loopback>`만 넣으면 대시보드까지 프록시로 가서 열리지 않고(K25), 대시보드 예외를 앞에 두면 효과가 없습니다(K26 — 에이전트 실측).

## 사용할 때 알아 둘 것 (UI 보고서 결정 19·20)
- `<-loopback>`으로 로컬 개발 서버까지 기록하면, 같은 PC의 **다른 로컬 도구의 비밀**(예: 주소에 `?token=`이 든 도구)도 기록되어 대시보드에 보입니다(X5).
- sumun을 켜 두고 `<-loopback>`을 쓰는 동안에는, 다른 웹사이트가 프록시를 통해 내 개발 서버에 요청할 수 있습니다(DNS 리바인딩 — 결정 19, SEC 큰 단위에서 다시 봄).
- 대시보드는 `localhost:…` 말고 **터미널에 나온 `http://127.0.0.1:…` 주소**로 여세요(결정 20 — IPv6 쪽 포트를 다른 프로그램이 잡는 경우를 피함).
- 안내 문구의 설정은 Chrome·Edge의 `--proxy-server` 기준입니다. Windows 시스템 프록시 설정 화면이나 Firefox에서는 확인하지 않았습니다(K29).
