# [INFRA-14] 승인된 방식 보정 O55~O61 반영        커밋: [RULE] 뒤 계획..(이 문서 커밋)

## 한 줄 요약
UI 보고서에서 승인하신 개발 방식 보정 7개를 넣었습니다. 6개(O55~O57, O59~O61)는 작업 지침(CLAUDE.md) 문구이고, 1개(O58)는 기계 검사(`check-method`)입니다. 이제 계획 커밋 제목에 적은 예상 번호를 진행 기록에서 찾지 못하면, 검사가 ✅ 대신 **"⚠ 확인 필요"**를 냅니다.

## 왜 필요했나 (O58)
UI-1 계획 커밋 제목은 "예상 E170~E172"였습니다. 그런데 진행 기록에서 E172 줄이 다른 블록 아래로 밀려, 검사가 E172를 예상으로 읽지 못했습니다. 그런데도 결과는 ✅였습니다. 검사는 **읽은 것만** 확인하므로, 읽지 못한 예상은 조용히 빠졌습니다.

```
 계획 커밋 제목: "[UI-1] 계획: … 예상 E170~E172"
        │  제목에서 번호를 펼침 → E170, E171, E172
        ▼
 progress.md 계획 절에서 읽은 예상: E170, E171, E173
        │  제목에 있는데 못 읽은 것 → E172
        ▼
 predictions-measured:
   실측·판정이 빠졌다      → ❌ 그대로 (근거 끝에 "E172를 읽지 못함"을 덧붙임)
   그 밖                   → ⚠ 확인 필요 "계획 제목의 예상 E172를 계획 절에서 읽지 못함(O58)"
 큰 단위 표: 위반으로 세지 않고 "⚠ 확인 필요 → UI-1 predictions-measured"로 따로 적음
```
- "⚠ 허용됨"(테스트 수정을 사용자가 허용함)과 "⚠ 확인 필요"(사람이 계획 절을 다시 볼 것)는 다른 뜻이라 글자를 나눴습니다.
- 계획 절에만 있고 제목에 없는 추가 예상(UI-1의 E173)은 경고하지 않습니다.

## 알아 둘 것
- 기계 검사의 ✅·⚠는 **형식**만 봅니다(O7). "⚠ 확인 필요"가 떴다면 progress.md 계획 절에서 그 번호의 예상 줄이 어디 있는지 사람이 봐야 합니다.
- UI-1의 진행 기록은 고치지 않았습니다(과거 기록은 그대로 둡니다). 그래서 앞으로 UI 검사를 돌리면 계속 "⚠ 확인 필요 → UI-1"이 보이는 것이 정상입니다.
