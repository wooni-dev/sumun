# [INFRA-11] 커밋 메시지 형식을 커밋 순간에 검사(O47)        커밋: 757f27b..(이 문서 커밋)

## 한 줄 요약
Claude가 커밋할 때 hook이 메시지 형식을 **커밋 순간에** 검사합니다. 전에는 PR이 끝난 뒤 `check-method`가 봐서, 틀린 커밋이 이미 이력에 들어간 뒤에야 알았습니다(TLS-4c, SEC-3에서 실제로 있었음). 실행 전에 막고, 그래도 빠져나간 것은 실행 뒤에 바로 알립니다.

## 두 단계
```
 Claude: git commit -q -F "C:/…/infra11-guard.txt"
   │
   ▼ ① 실행 전 (guard.mjs, 규칙 C)
   │   - 모양 검사: `git commit -F <절대 경로>`만 (-q, --allow-empty 허용)
   │     막는 것: -m, --amend, -C, --no-edit, --fixup, -F -(표준입력), $변수·상대 경로·~·/tmp,
   │             git 앞의 환경 변수·-c 설정, 같은 명령 안에서 그 파일을 쓰기
   │   - 내용 검사(scripts/commit-msg.mjs): 제목 "[ID] …", 둘째 줄 빈 줄, "- 왜: …", "- 검증: …"
   │     (글자 그대로·콜론 뒤 내용). BOM·UTF-16·깨진 UTF-8·\r만 있는 줄바꿈은 위반
   │   - 지금 HEAD와 시각을 .claude/state/commit-check.json에 기록
   ▼ git이 커밋을 만든다
   ▼ ② 실행 뒤 (commit-check.mjs)
       기록 뒤에 새로 생긴 "병합이 아닌" 커밋의 실제 메시지를 같은 함수로 검사
       → 틀리면 "멈추고 사용자에게 보고" 알림 (이미 생긴 커밋은 되돌리지 않음)
```
- ②가 있는 이유: 명령 글자만으로는 알 수 없는 경로가 많습니다. 별칭, `sh -c`, 스크립트 안의 커밋, cherry-pick·revert, PowerShell 파이프의 인코딩 변화 같은 것들입니다. 검토 에이전트가 우회 사례 78개를 찾았습니다(`docs/ai/infra11-cases.md`).
- 병합(`git merge`)은 검사하지 않습니다. 병합 메시지는 형식이 다르기 때문입니다.
- 사용자가 직접 한 커밋은 보지 않습니다. 기록 시점 전에 생긴 커밋이기 때문입니다.

## 켜는 표시 파일
규칙 C는 저장소에 `.claude/commit-rule.json`이 있을 때만 켜집니다. 기존 hook 테스트 6개가 `git commit -m`을 "허용"으로 기대하기 때문입니다. 그 테스트들은 규칙 A(테스트 파일 보호)의 오탐을 확인하는 것이라, 임시 저장소에 표시 파일이 없으면 원래 뜻대로 남습니다. 표시 파일을 지우면 꺼지는 것은 한계이고, 테스트가 "이 저장소에 표시 파일이 있다"를 확인합니다.

## 이 PR에서 생긴 일 (솔직하게)
- **잘못된 메시지로 커밋됨**: 연속 실패 멈춤 때문에 메시지 파일 쓰기가 막혔습니다. 그런데 같이 보낸 커밋 명령은 실행됐고, 임시 폴더에 남아 있던 지난 세션의 같은 이름 파일(PRX-2b 메시지)로 guard.mjs가 커밋됐습니다(5e7b491). 여쭌 뒤 `git reset --soft HEAD~1`로 되돌리고 다시 커밋했습니다(5b1e4a5). 이제는 Write 결과를 본 뒤에 커밋하고, 파일 이름에 노드 ID를 넣습니다(지침으로 넣을지는 O54로 여쭙니다).
- **승인 전 지침 추가**: 그 파일 이름 규칙을 CLAUDE.md에 바로 넣었다가, 승인 전 관찰이라 뺐습니다(O23). 빼면서 줄바꿈 하나를 잘못 지워서 한 번 더 고쳤습니다(d41b381 → 4a120b7).
- **연속 실패 멈춤**: 다음 커밋 몫인 테스트 6개가 커밋마다 실패로 세어져 멈춤이 켜졌습니다. 선택 창의 답으로는 풀리지 않았고 채팅 메시지가 필요했습니다(O53).

## 한계 (`docs/ai/infra11-cases.md` L1~L4)
- 표시 파일을 지우면 꺼집니다(지우면 git 이력에 남습니다).
- 실행 뒤 검사는 알리기만 합니다. 되돌리기는 사용자가 정합니다.
- `.git/` 직접 쓰기(별칭, git hook)는 실행 전에 보지 않습니다. 결과 커밋은 실행 뒤 검사가 봅니다.
- 형식은 맞는데 내용이 엉뚱한 메시지(이번 PRX-2b 사고)는 잡지 못합니다.
