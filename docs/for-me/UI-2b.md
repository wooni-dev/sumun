# [UI-2b] 포트 점유 검사의 self-connect 결함        커밋: 9c06ab3..(이 문서 커밋)

## 한 줄 요약
프록시와 대시보드는 시작하기 전에 "이 포트를 누가 쓰고 있나" 접속해 봅니다. 그런데 이 접속이 **자기 자신에게 연결되는** 경우가 있어서, 아무도 없는 포트를 "이미 쓰는 중"으로 오해했습니다. 그 오해를 고쳤습니다.

## 어떻게 생기나
1. TCP 접속에는 양쪽 끝에 포트가 하나씩 있습니다. 상대 포트(접속할 곳)와 내 포트(나가는 쪽, OS가 자동으로 줌)입니다.
2. Windows는 내 포트를 49152번 이상에서 **차례로** 나눠 줍니다.
3. 방금 57610번을 받았다면, 다음에 받을 내 포트는 57611번입니다.
4. 이때 57611번에 누가 있나 접속해 보면, 내 포트도 57611·상대 포트도 57611이 됩니다. 결국 **자기 자신과 연결**됩니다(TCP self-connect).
5. 검사는 "연결됐다 = 누가 쓰고 있다"로 보므로, 아무도 없는데 "이미 쓰는 중"이라고 판단했습니다.

```
  나가는 소켓 127.0.0.1:57611 ──접속──▶ 127.0.0.1:57611 (아무도 없음)
        └──────────── 같은 소켓 ────────────┘   → "연결됨" → 점유로 오해
```

- UI-2에서 대시보드를 프록시보다 먼저 열게 바꾸면서 이 순서가 맞아떨어졌습니다. 그래서 UI-3 중에 UI-1 테스트가 실패하며 드러났습니다.
- 실제 사용(8080·8081)에서는 이 범위 밖이라 거의 생기지 않습니다 [추측]. `--port 57610`처럼 49152 이상의 포트를 쓸 때 생길 수 있었습니다.

## 고친 것
- 연결되면 바로 **내 쪽 주소·포트와 상대 주소·포트가 같은지** 봅니다. 같으면 자기 자신이니 "아무도 없음"으로 판단합니다.
- 이 비교를 다른 프로그램이 흉내 낼 수는 없습니다. 실제로 누가 듣고 있는 포트는 OS가 내 포트로 주지 않기 때문입니다(에이전트 실험 15/15).
- 프록시 검사와 대시보드 검사(127.0.0.1·::1 두 번) 모두 고쳤습니다.
- 주의한 점:
  - 연결을 닫은 **뒤에** 값을 읽으면 내 쪽 정보가 사라져서, 고친 것이 조용히 효과가 없어집니다(Z4). 그래서 닫기 전에 읽습니다.
  - `'127.0.0.1'` 같은 글자와 비교하지 않고, 양쪽 값을 서로 비교합니다. `::ffff:127.0.0.1` 표기로 나오는 경우가 있기 때문입니다(Z5).

## 테스트 수정 (사용자 허용, `2ba1f82`)
- 결함을 고친 뒤 전체 테스트가 두 번 연속 실패했습니다. 실패한 것은 다른 UI-1 테스트였습니다.
- 원인은 테스트 쪽이었습니다 [추측]. UI-1 테스트는 OS가 준 임시 포트 P를 쓰는데, P+1은 PC 전체에서 **다음에 배정될 번호**입니다. 그래서 여러 테스트가 동시에 돌면 다른 테스트가 P+1을 먼저 가져갔습니다.
- 그래서 P를 임시 포트 범위 밖(20000~39999)에서 무작위로 고르고, P와 P+1이 비어 있는지 확인하게 바꿨습니다. 처음에는 P+1만 더 확인했는데 그것으로는 부족했습니다.
- 재현 테스트(UI-2b)의 반복 횟수도 5번에서 2번으로 줄였습니다. 기대값은 바꾸지 않았습니다.
- 확인한 것:
  - 수정 전 코드에서 UI-2b 재현 테스트는 여전히 3/3 실패합니다.
  - UI-1 구현 전 코드에서 UI-1 테스트는 4개가 실패합니다.
  - 이제 UI-1 테스트는 self-connect를 재현하지 않습니다. 그 몫은 UI-2b 테스트가 맡습니다.

## 고치지 않은 것 (UI 보고서 결정 항목)
검토 에이전트가 반대 방향 사례도 찾았습니다. **다른 프로그램이 듣고 있는데 놓치는** 경우로, 모두 `[::1]`(IPv6 루프백) 쪽입니다.
- W1·W2: 가짜 서버가 `[::1]`에서 검사 순간에만 접속을 거절하거나 미루면 검사를 지나칩니다. 그 뒤 `localhost:8081`로 가는 요청은 가짜가 받습니다.
- W3: 프록시 검사는 `[::1]`을 아예 보지 않습니다.
- W4: 우리가 시작한 **뒤에** 남이 `[::1]:8081`을 잡아도 막을 방법이 없습니다.
- 막으려면 대시보드를 `[::1]`에도 열거나, 안내 주소를 `127.0.0.1`로만 쓰는 방법 등이 있습니다. 앞의 것은 보안 규칙("127.0.0.1에만 바인딩")과 걸리므로 여쭤봐야 할 결정입니다.
- 지금 터미널에 나오는 주소는 `http://127.0.0.1:…`이라, 그 주소로 열면 이 문제는 생기지 않습니다 [추측].
