# [UI-2] 프록시 쪽 대시보드 차단        커밋: e5e5eaa..(이 문서 커밋)

## 한 줄 요약
브라우저가 대시보드 요청을 **프록시를 거쳐** 보내면, 이제 프록시가 그 요청을 대시보드에 넘기지 않습니다. 대신 "프록시를 거치지 않고 직접 여세요"라는 안내와 함께 403을 돌려줍니다. 평문 HTTP, HTTPS 터널(CONNECT), 복호화 모드에 모두 적용됩니다.

## 왜 필요했나
- 대시보드에는 방문한 모든 사이트의 쿠키와 토큰이 원본 그대로 있습니다.
- UI-1에서 대시보드 자신이 `Via: sumun`(우리 프록시를 거쳐 왔다는 표시)을 보고 막게 했습니다. 하지만 HTTPS 터널 안에는 Via가 없고 Host도 마음대로 쓸 수 있습니다(V13). 그래서 대시보드 혼자서는 "프록시를 거쳐 온 요청"을 확실히 구별할 수 없습니다.
- 또 프록시를 거친 대시보드 요청이 **기록**에 남았습니다. 그 기록에는 대시보드 토큰이 들어 있으니, 저장소에 토큰이 쌓이는 셈이었습니다(V21).
- 그래서 문을 두 겹으로 둡니다(ui-cases D-5). 프록시가 먼저 막고, 대시보드도 Via를 보고 막습니다.

## 무엇을 막나
"**이 PC 자신의 주소** + **대시보드 포트**"로 가는 요청입니다.
- 이 PC 자신의 주소: 127.x.x.x, ::1, 0.0.0.0, ::, `::ffff:127.0.0.1` 같은 IPv4-mapped 표기, `localhost`, `localhost.`
- 같은 주소를 다르게 쓴 표기도 막습니다: `127.1`, `2130706433`, `0x7f000001`, `HTTP://`, `evil@127.0.0.1`, `:08081`. 브라우저와 Node가 이 표기들을 모두 127.0.0.1로 바꾸기 때문에, 프록시도 **바꾼 뒤의 주소**로 판단합니다.
- 다른 포트는 막지 않습니다. 개발 중인 `localhost:3000` 같은 앱은 그대로 기록됩니다(G1).

```
브라우저 ─▶ 프록시 ─┬─ 대상이 글자로 보아 대시보드?(127.0.0.1:8081, localhost:8081 …)
                   │      → 403 + 안내. 기록·시작 알림 없음
                   ├─ 이름이면 한 번 해석 → 주소 중 하나라도 이 PC이고 포트가 대시보드?
                   │      → 403 + 안내. 거절 기록은 남음(error: proxy rejected 403)
                   └─ 아니면 지금까지처럼 중계·기록
```

### 이름은 왜 기록이 남나
- `rebind.example`처럼 루프백으로 풀리는 이름은, 해석해 봐야 대시보드인지 압니다.
- 해석하기 전에 "요청이 시작됐다"는 알림이 이미 나가므로, 거절 기록이 하나 남습니다.
- 이런 요청은 보통 공격 페이지(DNS 리바인딩)가 보낸 것이라 대시보드 토큰이 없습니다. 오히려 기록으로 남는 편이 낫습니다.

### 이름 해석은 한 번만
- 전에는 평문 요청의 이름을 Node가 **연결할 때** 따로 해석했습니다.
- 그대로 두면 "검사할 때는 남의 주소, 연결할 때는 127.0.0.1"이 되어 검사를 비켜 갑니다(V10).
- 그래서 평문도 프록시의 `lookup`으로 한 번만 해석합니다. 그 주소로 검사하고, 같은 주소로 연결합니다.

## 실행하면
`npm start` 순서가 바뀌었습니다.
- 대시보드를 **먼저** 열고, 그 실제 포트를 프록시에 알려 줍니다. 그래서 기본 포트(프록시 + 1)가 차서 다른 포트로 열렸을 때도 실제 포트를 막습니다.
- 프록시를 거친 대시보드 요청이 처음 오면, 터미널에 안내 줄이 **한 번만** 나옵니다.

```
sumun: 대시보드로 가는 요청이 프록시로 들어와 거절했습니다. 대시보드는 프록시를 거치지 않고 직접 여세요 — 브라우저(또는 Windows) 프록시 설정의 예외 목록에 127.0.0.1과 localhost를 넣으세요(이 안내는 한 번만 나옵니다).
```

👉 **해야 할 것**: 브라우저나 Windows 프록시 설정에서 "프록시를 사용하지 않을 주소"에 `127.0.0.1;localhost`를 넣으세요. 그러면 대시보드가 프록시를 거치지 않습니다.

## 이 PR에서 생긴 일 (솔직하게)
- 검토 에이전트의 실험 스크립트 하나(r5)가 **CA 개인키를 스크립트 옆에** 만들게 되어 있었습니다. 저장소로 옮기면 저장소 안에 키가 생깁니다. 그래서 옮길 때 OS 임시 폴더로 바꿨습니다(보안 규칙: 개인키는 저장소 밖).
- 브랜치를 만들 때 `git checkout`과 테스트 파일 읽기를 한 명령에 넣었더니 hook이 막았습니다(의도한 보수적 동작). 명령을 나눴습니다.
- `npm test -- test/tls`처럼 **폴더**를 넘기면 실행기가 파일을 찾지 못해 "실패 1"이 됩니다. 파일 목록(`test/tls/*.test.ts`)으로 다시 돌렸습니다. 코드 문제는 아닙니다.
- 코드를 고치는 스크립트가 따옴표 처리를 잘못해 두 번 실패했습니다. 한 번은 아무것도 바꾸지 않았고, 한 번은 문자열 안에 줄바꿈을 넣었습니다. 둘 다 커밋 전에 고쳤습니다.
