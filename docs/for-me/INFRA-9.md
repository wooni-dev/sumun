# [INFRA-9] 큰 단위 테스트가 "대기 중"일 때 멈춤 장치를 비켜 가게 하는 좁은 예외        커밋: 536afb0..(이 문서 커밋)

## 한 줄 요약
큰 단위 테스트(예: TLS 전체 흐름)는 마지막 작은 단위가 끝날 때까지 실패하는 게 정상이다. 그 실패를 "3번 연속 실패하면 멈춤" 장치가 세지 않게 했다. 다만 **판정은 테스트 코드가 아니라 실행기가 직접** 하고, 조건을 아주 좁게 두었다.

## 왜 필요했나 (실측)
Node의 "할 일(todo)" 표시를 붙인 테스트는 실패해도 종료 코드가 0이다. 그런데 junit 결과에는 실패 기록이 그대로 남아서, 연속 실패 카운터가 세고 3번째에 작업을 멈췄다 [확인됨: 임시 폴더 실측].

## 예외가 되는 조건 (전부 만족해야 함)
1. 파일 이름이 `test/<폴더>/<큰단위ID>-T.test.ts` 그대로다(대소문자까지). ID는 목적 나무의 **큰 단위**(`├ [TLS]`)다.
   - 예외가 아닌 예: 이미 있는 `PRX-T-regression.test.ts`, `TLS-t.test.ts`, `test/` 밖의 파일
2. todo 이유가 정확히 `대기: src/…`다. 예: `대기: src/tls/mitm.ts`
3. **실행기가 직접 확인했을 때** 그 파일이 아직 없다. 생기면 todo가 풀린 것이니 실패를 다시 센다.
4. 그 `-T` 파일에 `export`가 없다. 있으면 다른 파일이 그 함수를 빌려 테스트를 등록하고 예외를 받을 수 있다(검토자가 실측으로 보여 준 우회).

검토자가 찾은 중요한 사실: 테스트는 **실패한 뒤에 스스로 todo로 바꿀 수 있다**(`t.todo()`). 그래서 "테스트가 todo라고 하니 예외"로 하면 안 되고, 실행기가 조건을 직접 본다. 웹 개발로 치면 클라이언트가 보낸 `isAdmin: true`를 믿지 않고 서버가 권한을 다시 확인하는 것과 같다.

## 실제로 돌려 본 결과 (`node scripts/probe/infra9-bigtodo.mjs`, 임시 폴더의 작은 프로젝트)
| 상황 | 결과 |
|---|---|
| 대기 중인 큰 단위 테스트를 3번 실행 | 셈 0, 멈춤 없음, "큰 단위 대기(todo) TLS: 1개, 그중 실패 1개" 표시 |
| 일반 테스트가 3번 실패 | 셈 1 → 2 → 3, **3번째에 멈춤**(지금과 같음) |
| 대기 파일을 만든 뒤 큰 단위 테스트 실패 | 셈 1 — 이제 센다 |

## 큰 단위가 끝날 때의 확인
`node scripts/check-method.mjs --id TLS`의 새 규칙 `big-unit-todo`가 마지막 `npm test` 기록(`.claude/state/last-run.json`)을 읽는다. 조건은 "대상 인자 없이 전체를 실행했고, 실패 0, 그 큰 단위 대기 0"이다. 보고서의 문구가 아니라 실행기가 쓴 기록으로 판정한다. 지금 `--id PRX`로 돌리면 ✅다.

## 범위 밖으로 남긴 것 (원래 있던 빈틈, 검토자가 함께 찾음)
- ⚠ **테스트 코드가 `.claude/state/`(카운터 파일)에 직접 쓸 수 있다.** hook은 Claude가 실행하는 명령만 검사하고, `npm test`가 실행하는 테스트 코드의 내용은 보지 않는다. 멈춤 장치 전체를 무력화할 수 있다 → 다음에 따로 다루자고 제안한다.
- `{ skip }`이나 `--test-skip-pattern`으로 테스트를 건너뛰면 셈이 초기화된다.
- 같은 이름의 테스트 두 개가 셈을 섞는다. 부모 테스트의 실패가 junit에서 빠진다.
