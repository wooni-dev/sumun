# [STO-4] 프록시 연결과 실행 진입점        커밋: e77db13..(이 문서 커밋)

## 한 줄 요약
저장소를 프록시와 `npm start`에 연결했다. 이제 프록시를 거친 요청은 모두 메모리 저장소에 쌓인다(상한 안에서). 이 단위로 **STO 큰 단위 테스트(STO-T)가 대기에서 풀려 실제로 통과**한다.

## 연결 모양
```js
const store = createStore();
startProxy({ port, ...attachStore(store) });   // onFlowStart, onFlow 두 콜백이 함께 들어간다
```
`npm start`(`src/index.ts`)에서는 요약 줄을 그대로 찍는다. 그래서 기록 콜백만 감싸서 "요약 줄 → 저장" 순서로 부른다. 저장에서 문제가 나도 요약 줄은 남는다.
```
 curl ─▶ [프록시] ── 시작 알림 ──▶ store.addStart   (진행 중)
                  ── 기록 ──────▶ 요약 줄 출력 ─▶ store.addFlow (완료)
```

## 지키는 약속
| 약속 | 왜 |
|---|---|
| 시작·끝 콜백을 **함께** 돌려준다 | 하나만 연결하면 "진행 중"만 쌓이거나 시작이 빠진다(sto-cases B2) |
| 저장소 하나에 프록시 하나. 두 번째 연결은 오류 | 프록시마다 id가 1부터 시작한다. 둘이 한 저장소를 쓰면 기록이 덮이거나 엉뚱하게 짝지어진다(결정 S-7) |
| 프록시를 닫은 **뒤에** 도착한 기록도 저장 | 닫을 때 진행 중이던 요청은 닫힌 뒤에 `aborted` 기록으로 온다 [확인됨: sto-cases E13]. 실제로 있었던 요청이다 |
| 종료(Ctrl+C) 때 저장소를 출력·저장하지 않음 | 기록에는 쿠키가 원본 그대로 있다. 디스크에 쓰지 않는다는 결정(PRX-2) |

쿠키·쿼리·본문에 넣은 표식이 터미널에 하나도 나오지 않았다. STO 큰 단위 테스트도 실제 curl을 쓴다(평문 POST, 닫힌 포트).

## 아직 안 되는 것
저장소에 쌓인 기록은 아직 **바깥에서 볼 수 없다.** 다음 큰 단위 UI(대시보드)가 `store.list()`, `store.get(id)`, `store.subscribe()`로 화면에 보여 준다.
