# [SEC-3] 루트 CA 등록·해제·상태 명령        커밋: 8e2e616..(이 문서 커밋)

## 한 줄 요약
sumun 루트 CA를 Windows(현재 사용자)에 **등록·해제·확인하는 명령**을 만들었습니다. 사용자님이 직접 등록하고 해제해서, 실제 Chrome으로 HTTPS가 경고 없이 열리고 해제 뒤에는 다시 경고가 나는 것까지 확인했습니다.

## 쓰는 법 (PowerShell, 관리자 아닌 일반 창)
```powershell
cd D:\secretary\sumun
npm.cmd run ca -- status      # 지금 상태(읽기만)
npm.cmd run ca -- install     # 등록: 화면 확인 → 영어로 yes → Windows 창에서 지문 비교 후 "예"
npm.cmd run ca -- uninstall   # 해제: 영어로 yes → Windows 창에서 "예"
```
- PowerShell에서 `npm`만 쓰면 실행 정책 때문에 `npm.ps1`이 막힐 수 있습니다("이 시스템에서 스크립트를 실행할 수 없으므로…"). 보안 설정은 바꾸지 말고 **`npm.cmd`**를 쓰세요. `node src\ca-cmd.ts install`도 같습니다.
- 등록한 뒤 HTTPS 내용을 보려면 `npm.cmd start -- --decrypt`로 프록시를 켜고, 브라우저 프록시를 `127.0.0.1:8080`으로 둡니다.
- curl로 시험할 때는 `--ssl-no-revoke`가 필요합니다. sumun CA에는 폐기 목록 서버가 없어서 Windows curl(Schannel)이 폐기 여부 확인에서 실패하기 때문입니다.
- **등록해 두는 동안**에는 이 사용자의 Chrome·Edge뿐 아니라 Windows TLS 프로그램(PowerShell, .NET 등)도 sumun CA를 믿습니다. Firefox도 설정에 따라 Windows 루트를 믿을 수 있습니다. 개인키(`%LOCALAPPDATA%\sumun\ca\ca-key.pem`, 본인만 읽기)가 새면 아무 사이트나 위조될 수 있으니 안 쓸 때는 해제하세요.

## 안전장치 (검토 에이전트가 찾은 사례 52개 중 이 단위에서 막은 것)
| 위험 | 막는 방법 |
|---|---|
| 스크립트나 AI가 대신 yes를 넣음 | 대화형 터미널에서 사람이 친 입력만 받는다. 파이프 입력은 거부한다(그래서 등록·해제는 사용자님이 직접) |
| 관리자 창에서 실수해 컴퓨터 전체에 적용 | 관리자(승격) 창이면 거부한다 |
| CA 파일에 인증서를 몰래 하나 더 넣음 | 파일에 인증서가 정확히 하나가 아니면 거부한다. 등록은 검사한 그 하나만 임시 파일로 다시 만들어서 한다 |
| 엉뚱한 인증서 삭제 | 40자리 지문으로만 지운다. certutil은 같은 값을 다른 인증서의 일련번호·이름으로도 맞추므로, 겹치면 지우지 않는다 |
| 이름만 sumun인 다른 인증서 | 옛 sumun CA는 이름 형식과 인증서 모양이 모두 맞아야 후보다. 하나씩 묻는다 |
| 비슷한 이름으로 위장(`ѕumun` 키릴 문자, `Uumun`, 보이지 않는 글자) | status가 "이름이 비슷한 인증서"로 경고한다(지우지는 않음) |
| 인증서 이름에 화면을 조작하는 글자 | 출력 전에 이스케이프한다 |
| 가짜 certutil·환경 변수 조작 | `C:\Windows\System32\…` 절대 경로로만 실행한다 |
| "성공" 글자만 믿기 | 등록·해제 뒤 저장소(레지스트리)를 다시 읽어 지문으로 확인한다 |
| PowerShell의 "현재 사용자 Root"는 컴퓨터 저장소까지 합쳐서 보여 줌 | 사용자 저장소는 레지스트리로 따로 읽고, 컴퓨터 쪽에 있으면 "이 명령으로 지울 수 없음"이라고 따로 보인다 |
| CA 폴더가 링크이거나 다른 사용자가 쓸 수 있음 | 등록을 거부한다 |

## 실제로 확인한 것 (사용자님 PC, 2026-11-08)
| 확인 | 결과 |
|---|---|
| 등록 화면의 SHA-1 = Windows 창의 지문 | 같음(사용자님 확인) |
| 등록 뒤 status | 사용자 Root 등록됨, 컴퓨터 Root 없음 |
| 등록 뒤 Chrome(임시 프로필, 헤드리스) | `https://example.com/` 경고 없이 열림, 프록시 기록 `GET example.com:443 200` |
| 등록 뒤 curl | 옵션 없이 실패(종료 코드 35), `--ssl-no-revoke` 붙이면 HTTP 200 |
| 루트의 용도 제한(서버 인증만)을 Windows가 지키나 | 지킴. 코드 서명용 인증서는 `CERT_E_WRONG_USAGE`로 거부됨 → 키가 새도 프로그램 서명은 위조할 수 없음 |
| 해제 뒤 status·레지스트리 | 등록 안 됨, 0개 |
| 해제 뒤 Chrome | `ERR_CERT_AUTHORITY_INVALID`(다시 경고) |

관찰: 등록 상태에서도 Chrome이 몰래 연 `accounts.google.com`은 우리 인증서를 거부했습니다(`tls-handshake`). 구글 계정 도메인은 별도 보호를 받는 것으로 보입니다 [추측]. 이런 사이트는 sumun으로 내용을 볼 수 없습니다.

## 실측 중에 찾은 결함 1건 (고침)
처음 해제하셨을 때 "예를 눌렀는데 해제됨을 못 봤다"고 하셨고, 실제로 인증서가 남아 있었습니다. 원인 후보는 두 가지였습니다. ① 터미널에 영어 `yes` 대신 `예`를 입력해 취소됨(이 경우 Windows 창도 뜨지 않습니다) ② Windows 창에서 "예"를 눌렀는데 삭제 실패. 프로그램이 화면 말고는 아무 기록을 남기지 않아서 **창을 닫자 어느 쪽인지 알 수 없었습니다.** 이것이 결함이었습니다. 그래서:
- 작업 기록을 `%LOCALAPPDATA%\sumun\ca-command.log`에 남기게 했습니다(단계·지문·입력 결과·certutil 종료 코드·최종 결과, 키·비밀 없음).
- 질문을 "영어로 yes를 입력하세요"로 바꾸고, `예`·`네`·`y`를 입력하면 여전히 취소하되 "영어 yes를 입력해야 합니다"라고 알려 줍니다.

고친 뒤 다시 해제하셨고, 기록에 `확인 입력 "yes" → 진행 → certutil -delstore 종료 코드 0 → 해제됨`이 남았습니다. 처음 실패가 ①이었는지 ②였는지는 끝내 확인할 수 없습니다.
