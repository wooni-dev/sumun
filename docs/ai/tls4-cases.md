# TLS-4 보안·경계 사례: TLS 종료 후 복호화한 요청 기록 (O10: 검토 에이전트 제안)

출처: 2026-11-08, 별도 컨텍스트의 검토 에이전트가 **명세만 보고** 제안(약 70개 + 결정 11개) [추측: 코드 없음]. 근거: RFC 9110/9112/8446/6066/7301, Durumeric 외 2017(HTTPS 가로채기 제품 연구), Superfish·Komodia.
명세: `startProxy({ ca, upstreamCA })` — CONNECT → 200 → 같은 소켓에서 프록시가 TLS 서버로 핸드셰이크(issueCert 인증서) → 터널 안 HTTP/1.1 요청을 기록·중계 → 목적지에는 새 TLS(검증 켬, 공개 CA + upstreamCA) → 믿을 수 없으면 터널 안 502·`bad-certificate`.
배정: **4** = TLS-4, **4b** = TLS-4b(견고성 — 2026-11-08 나눔), **SEC-3** = 등록 단위(실제 브라우저), **문서** = 하지 않는다고 적어 둠.
이전 단위에서 넘어온 것: tls1-cases T1~T5, tls3-cases 47~55 → 아래에 합쳐 배정.

|---|---|---|---|

## B. SNI와 CONNECT 호스트 (사용자 결정 1: CONNECT 기준)
| # | 상황 | 기대 | 배정 |
|---|---|---|---|
| B1·B3 | SNI = CONNECT / SNI 없음 | CONNECT 호스트 인증서 | 4 |
| B2 | SNI ≠ CONNECT | 인증서·목적지 모두 CONNECT 기준, **SNI가 목적지 주소를 정하지 않음**, 기록에 SNI 표시 | 4 |
| B4·B5 | SNI가 IP / CONNECT 호스트가 IP | SNI 무시 / IP SAN 인증서 | 4 |
| B6 | `A.Test`, 끝점 | 같은 캐시 키, 발급 1번 | 4 |
| B7 | SNI가 와일드카드·255자 초과·제어 문자 | 그 이름으로 발급하지 않음(CONNECT 기준이라 영향 없음), 프로세스 유지 | 4b |

## E. 터널 안 요청 (사용자 결정 2: Host가 다르면 421)

## 결정 (사용자 결정은 표시, 나머지는 추천으로 진행 — TLS 보고서에 올림)
| # | 항목 | 정한 것 | 이유 |

| 3 | ca가 있는데 TLS가 아닌 바이트 | 닫고 기록(TLS-4b) | 검사 경로를 하나로 |
| 4 | 목적지 불신 알림 | 터널 안 502 (**사용자 2026-11-08**, TLS-T와 같음) | 이유를 읽을 수 있다 |
| 5 | ALPN h2만 | 실패·기록(TLS-4b) | h2를 1.1로 해석하지 않음 |
| 6 | 터널 안 Upgrade | 거부(TLS-4b) | 범위 밖, 기록이 거짓이 되지 않게 |

| 10 | 폐기 확인 | 하지 않음(문서) | 비용·오프라인 테스트 |
