# TLS-3 보안·경계 사례: 사이트별 인증서 즉석 발급 (O10: 검토 에이전트 제안)

출처: 2026-11-08, 별도 컨텍스트의 검토 에이전트가 **명세만 보고** 제안(55개 + 결정 13개) [추측: 코드 없음]. 근거: RFC 5280·6125·9525, CA/B BR, 브라우저·Schannel·Node tls 요구, 알려진 MITM 사고.
명세: `issueCert(ca, hosts)` → `{ certPem, keyPem }`. 루트 CA로 서명한 말단 서버 인증서와 그 키. TLS-4가 CONNECT·SNI의 이름으로 부른다.
배정: **3** = TLS-3, **4** = TLS-4(프록시 문맥이 있어야 시험할 수 있음).

## A. 말단 필드 (전부 3)
| # | 기대 |
|---|---|
| 1 | v3, basicConstraints cA=FALSE(critical) |
| 2 | keyUsage = digitalSignature·keyEncipherment만, critical (keyCertSign·cRLSign 없음) |
| 3 | EKU = serverAuth만 |
| 4 | SAN이 반드시 있다(CN만으로는 안 됨 — Chrome 58+) |
| 5 | IP는 iPAddress(4·16바이트), dNSName에 IP 글자를 넣지 않음 |
| 6 | AKI = 루트 SKI, 말단 SKI 있음 |
| 7 | 말단 issuer DN = 루트 subject DN(바이트까지) |
| 8 | sha256WithRSAEncryption |
| 9 | 일련번호 100개 모두 다름, 양수, ≤ 20옥텟, ≥ 64비트 난수 |
| 10 | 루트를 다시 만든 뒤에도 issuer+serial이 겹치지 않음(난수 128비트로) |
| 11 | notBefore ≤ 지금(1시간 전), notAfter ≤ min(30일, 루트 만료) |
| 12 | 말단 키 RSA 2048·e=65537, `tls.createSecureContext` 성공 |
| 13 | 말단 subject ≠ 루트 subject |

## B. hosts 입력 (전부 3)
| # | 입력 | 기대 |
|---|---|---|
| 14·15 | `[]`, 배열 아님, `[123]`, `[null]`, `['']` | 거부 |
| 16·17 | `*.example.com`, `*`, `*.com`, `f*o.example.com`, `a.*.com` | 거부(사용자 결정 2) |
| 18 | `Example.COM.` | `example.com`으로 정규화 |
| 19·20 | `bücher.de` / `xn--bcher-kva.de` | 거부 / 허용(결정 6) |
| 21 | `[::1]`, `0:0:0:0:0:0:0:1`, `::FFFF:127.0.0.1` | 괄호 제거·16바이트 / IPv4-mapped 거부(결정 8) |
| 22 | `127.1`, `2130706433`, `0x7f.0.0.1`, `0177.0.0.1` | 거부 |
| 23·24·25 | NUL, 공백·탭·줄바꿈, 쉼표·`/`·`=`·`+`·`CN=` | 거부(결정 10: 공백도 거부) |
| 26 | `example.com:443` | 거부 |
| 27·28 | 레이블 64자, 전체 254자 / 빈 레이블, 하이픈 시작·끝 | 거부 (63자 레이블·253자는 허용) |
| 29·32 | `_dmarc.example.com` / 한 레이블(`myhost`), `localhost`, `com`, `co.uk` | 밑줄 허용, 한 레이블은 localhost만(결정 9) |
| 30 | 중복(`a.com`, `A.com`, `a.com.`) | SAN에 1개 |
| 31 | 51개 이상 | 거부(결정 12: 50) |
| 33 | 루트 CN과 같은 이름 | 허용, subject는 루트와 다름 |
| 34 | 호출 뒤 hosts·ca | 바뀌지 않음 |

## E. 성능 (45·46 = 3, 47~50 = 4)
| # | 기대 | 배정 |
|---|---|---|
| 45 | 1회 발급 동안 이벤트 루프 최대 지연 ≤ 50ms(결정 13) | 3 |
| 46 | 서로 다른 호스트 동시 20번: 모두 성공·일련번호 다름·지연 기준 안 | 3 |
| 47~50 | 같은 호스트 동시 요청은 한 번만 발급, 캐시 키(정규화 이름 + 루트 지문), 상한(LRU), 만료 임박 재발급, 캐시 오염 없음 | 4 |

## F. TLS-4 (전부 4)
51 SNI ≠ CONNECT 호스트 / 52 SNI 없음·IP SNI / **53 목적지 인증서 검증 실패를 신뢰되는 가짜 인증서로 숨기지 않음(가장 흔한 MITM 제품 결함 — TLS-T의 bad-certificate 502가 이것)** / 54 HSTS·핀닝은 우회하지 않음 / 55 Firefox의 Windows 루트 사용 여부(실측)

## 결정 (사용자 결정은 표시, 나머지는 추천으로 진행 — TLS 보고서에 올림)
| # | 항목 | 정한 것 | 이유 |
|---|---|---|---|
| 1 | 말단 유효 기간 | 30일, notBefore 1시간 전, 루트 만료일로 자름 (**사용자 2026-11-08**) | 메모리에서 다시 만들면 되니 짧아도 비용이 적다 |
| 2 | 와일드카드 | 금지 (**사용자 2026-11-08**) | SNI가 정확한 이름을 준다. 대표 범위가 가장 좁다 |
| 3 | 말단 키 | 호출마다 새 RSA 2048(비동기 생성). 루트 키 재사용 금지 (**사용자 2026-11-08**) | 새어도 그 사이트에 한정 |
| 4 | 서명 | TBS는 forge, 서명은 Node `crypto.sign(…, 콜백)` | forge 동기 서명은 67~148ms 동안 루프를 막는다(R-2). 실측으로 확인 |
| 5 | 캐시 | TLS-4 | issueCert는 순수 함수로(테스트 쉬움) |
| 6 | 비ASCII 이름 | 거부(punycode만) | SNI는 이미 A-label. 변환기 차이 위험 없음 |
| 7 | CN | 첫 호스트(64자 이하일 때), 매칭은 SAN | 사람이 보기 쉽게 |
| 8 | IPv4-mapped IPv6 | 거부 | 매칭이 모호, 정상 입력에 거의 없음 |
| 9 | 밑줄·한 레이블 | 밑줄 허용, 한 레이블은 `localhost`만 | 실제 사이트 이름은 막지 않되 이상한 이름은 막음 |
| 10 | 공백 | 거부(자르지 않음) | 호출자 버그를 드러냄 |
| 11 | 루트 만료 임박 | 말단 만료를 자르고, 남은 기간 1일 미만이면 거부 | 조용한 실패 방지 |
| 12 | hosts 개수 | 50 이하 | 자원 보호(TLS-4는 1개) |
| 13 | 지연 기준 | 50ms(실측 뒤 확정) | 판정 기준(O38) |
