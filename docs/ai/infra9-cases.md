# INFRA-9 우회 사례: 큰 단위 테스트(`*-T.test.*`)의 todo 실패를 연속 실패로 세지 않는 예외 (O10)

출처: 2026-11-07, 별도 컨텍스트의 검토 에이전트가 명세만 받고 제안(28개). 일부는 저장소 밖 임시 폴더에서 Node v24.21.0으로 실측했다 [확인됨: 검토자 실측]. 작업자의 구현안은 알려 주지 않았다.
배정: **9** = INFRA-9 테스트, **규칙** = CLAUDE.md, **밖** = 범위 밖(progress.md 기록).

## 먼저 알아 둘 Node 동작 (검토자 실측)
- `t.todo()`는 본문 실행 중에도 부를 수 있다 → 실패한 뒤 todo로 바꿀 수 있다. **판정을 테스트 코드에 맡기면 안 된다.**
- junit의 `file` 속성은 `test()`를 호출한 파일이다 → 일반 파일이 `-T` 파일의 함수로 테스트를 등록하면 `-T`로 기록된다.
- `{todo: 0}`도 todo가 된다. `describe({todo})`, 하위 테스트 todo도 같은 모양으로 나온다.
- 부모 테스트의 실패(하위 테스트 뒤)는 junit에 testcase가 없어 parseJunit이 세지 못한다(원래 있던 빈틈).
