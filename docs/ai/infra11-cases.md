# INFRA-11 사례: 커밋 메시지 형식 규칙 C (O10: 검토 에이전트가 제안)

출처: 2026-11-08, 별도 컨텍스트의 검토 에이전트가 `.claude/hooks/guard.mjs`(main a3889fa)를 읽고 추론한 결과 [추측: 명령은 실행하지 않음]. 확인한 것은 git 2.55.0.windows.5, 별칭·commit.template 없음, `check-method.mjs` 75행 [확인됨: 에이전트]. 작업자의 해결안은 알려 주지 않았다.
규칙 C = Claude가 만드는 커밋의 메시지는 `[ID] 제목` / 빈 줄 / `- 왜: …` / `- 검증: …` 형식(CLAUDE.md "커밋 메시지 형식"). 병합 커밋은 제외.

## 사용자 결정 (2026-11-08)
- D1 장치: Claude hook. 실행 전(guard.mjs) + 실행 뒤(새 hook) 둘 다. git commit-msg hook은 쓰지 않는다.
- D2 실행 전: 커밋은 `git commit -F <절대 경로 파일>` 한 가지 모양만(`-q`, `--quiet`, `--allow-empty`, `-C <절대 경로>` 전역 옵션, `--no-pager` 허용). 나머지 메시지 출처·옵션·변수 경로·상대 경로는 막는다. 파일 내용을 검사한다.
- D3 실행 뒤: 명령 직전(guard가 기록한 HEAD·시각) 뒤에 새로 생긴 **병합이 아닌** 커밋의 실제 메시지(`git log %B`)를 같은 함수로 검사한다. 틀리면 "멈추고 사용자에게 보고"를 알린다(이미 생긴 커밋은 되돌리지 않는다).
- D4 병합(`git merge`)은 검사하지 않는다.
- D5 단위: O47만 INFRA-11. O48~O52는 INFRA-12.
- D6 켜는 표시 파일: 규칙 C는 저장소에 `.claude/commit-rule.json`이 있을 때만 켠다. 기존 hook 테스트 6개(`hooks-data-gt.test.mjs`, `hooks-normal-regression.test.mjs` — 규칙 A의 오탐 검사)가 `git commit -m`·`-F -`를 "허용"으로 기대하기 때문이다. 표시 파일을 지우면 꺼지는 것은 한계(아래 L1).

## 한계
- L1 표시 파일 `.claude/commit-rule.json`을 지우면 두 검사가 모두 꺼진다. 저장소에 커밋되어 있으므로 지우면 git 이력에 남는다. 테스트가 "이 저장소에 표시 파일이 있다"를 본다.
- L2 실행 뒤 검사는 이미 생긴 커밋을 알릴 뿐이다. 되돌리기는 사용자가 정한다.
- L3 `.git/` 직접 쓰기(별칭, git hook, commentChar 설정)로 메시지를 바꾸는 것은 실행 전에 보지 않는다. 결과 커밋은 실행 뒤 검사가 본다.
- L4 같은 시각에 도구를 두 개 돌리면 guard의 기록(HEAD·시각)이 덮일 수 있다.
