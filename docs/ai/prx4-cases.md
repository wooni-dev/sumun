# PRX-4 보안·경계 사례 (O10: 검토 에이전트 제안)

출처: 2026-11-07, 별도 컨텍스트의 검토 에이전트가 **명세만 보고** 제안 [추측: 코드 없음]. 명세: `npm start` / `node src/index.ts [--port N]`, 포트 1~65535 정수만, 시작 줄 1개, 요청마다 요약 한 줄(메서드, 호스트, 상태 또는 실패 코드, 소요 시간 — 경로·쿼리·헤더·본문·쿠키는 출력 안 함), Ctrl+C로 종료, 파일 저장 없음.
배정: **4** = PRX-4 자동 테스트, **수동** = 사람이 실제 터미널에서 확인, **나중** = 표시한 단계.

## K. 요약 줄을 통한 유출 (전부 4)
| # | 입력 | 기대 |
|---|---|---|
| K1 | `http://user:SECRET@host/` | 호스트 칸에 userinfo 없음 |
| K2 | 해석할 수 없는 대상, origin-form `GET /path?token=SECRET` | 호스트 칸은 `-`, 경로·쿼리 없음 |
| K3 | CONNECT 대상에 경로·쿼리 | 출력에 없음(CONNECT는 기록하지 않으므로 줄 자체가 없음) |
| K4~K7 | ESC·OSC 시퀀스, CR/LF, C1(0x80~0x9F), U+2028·NEL | 출력 바이트에 제어 문자 없음(이스케이프), 요청당 정확히 한 줄 |
| K8 | bidi 제어 문자, IDN | bidi는 이스케이프, IDN은 punycode |
| K9 | 아주 긴 호스트 | 호스트 255자, 줄 512자에서 자르고 `…` |
| K10 | 이상한 포트 | 해석된 target의 숫자 포트만 |
| K11 | 이상한 메서드 | 원본 바이트를 찍지 않음(이스케이프) |
| K12 | 실패 칸에 err.message | 정해진 코드 목록만 |
| K13 | Host 헤더 ≠ 실제 대상 | 실제로 연결한 대상(target)만 |
| K14 | 모든 필드에 표식 | 요약 함수가 다른 필드를 읽지 않음 |

## L. 포트·인자 (L1~L8, L10 → 4 / L9 → 문서)
L1 경계값 0·65536·-1 거부 / L2 `8080abc`, `8080.0`, `1e3`, `0x1F90`, `+8080`, `08080`, `NaN` 거부 / L3 빈 값·공백·값 없음 거부 / L4 큰 수 거부(문자열 단계에서) / L5 전각·아랍 숫자 거부 / L6 중복 인자 거부 / L7 모르는 인자(`--host`, `-p`, 위치 인자) 거부 / L8 환경 변수(PORT, HOST) 무시 / L9 `npm start --port N`은 npm이 가져감 → 사용법에 `npm start -- --port N` / L10 오류 메시지 속 입력값도 이스케이프·길이 제한

## M. 시작·종료
| # | 상황 | 기대 | 배정 |
|---|---|---|---|
| M1 | 포트 점유 | 한 줄 오류, 종료 코드 1, 스택 없음, 시작 줄 없음 | 4 |
| M2 | 시작 줄 시점 | listen 성공 뒤에만, 실제 주소 | 4 |
| M3 | 다른 앱이 0.0.0.0:P 사용 중 | 시작 거부 | 이미 됨(PRX-1c A9) |
| M4 | Windows 예약 포트(EACCES) | 구분되는 메시지 | 수동(환경 의존) |
| M5~M7 | 열린 연결 중 Ctrl+C, 두 번, 창 닫기 | 정해진 시간 안에 끝남, 파일 없음 | 수동(Windows의 `child.kill('SIGINT')`는 처리기를 거치지 않음) |
| M8 | 요약 함수 예외 | 프록시 계속, 오류 줄에 기록 내용 없음 | 4 |
| M9 | 구독자 비동기 거부 | 프로세스 생존 | 이미 됨(PRX-2 I2) |
| M10 | 종료 코드 | 인자 오류·시작 실패 1 | 4(실패 쪽) |

## N. 나중
N1 HTTPS에서 CONNECT 호스트·SNI·내부 Host 불일치 표시 → TLS / N2 대시보드 HTML 이스케이프 → UI / N3 `NODE_OPTIONS=--inspect` 경고 → UI 전 / N4 같은 PC의 다른 프로세스·WSL2도 127.0.0.1:8080을 씀 → 접근 제어 검토 / N5 기록 보관 상한 → STO / N6 출력 리다이렉트 → 출력이 늘 때마다 / N7 런타임 경고가 출력에 섞임 → 테스트에서 확인
