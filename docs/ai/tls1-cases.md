# TLS-1 보안·경계 사례: CONNECT 불투명 터널 (O10: 검토 에이전트 제안)

출처: 2026-11-07, 별도 컨텍스트의 검토 에이전트가 **명세만 보고** 제안(40개 + 결정 12개) [추측: 코드 없음]. 근거 표시: [RFC] 9110 9.3.6, 9112 3.2.3 / [사례] SSRF·DNS 리바인딩·로그 인젝션.
명세: CONNECT host:port → 목적지에 TCP 연결 → `200 Connection Established` → 양쪽 바이트를 해석 없이 이어 줌. 터널마다 기록 하나(host:port, 양방향 바이트 수, 시간, 실패). 내용은 기록하지 않음. 연결 실패 502, 연결 타임아웃 504.
배정: **1** = TLS-1, **1b** = TLS-1b(견고성), **4** = TLS-4에서 다시.

## P. 대상 해석 (전부 1)
| # | 입력 | 기대 |
|---|---|---|
| P1 | 포트 없음, `:0`, `:65536`, `:-1`, `:+443`, `:443abc`, `:0x1bb`, `:00443` | 400, 연결 시도 없음 |
| P2 | `user:pass@host:443` | 400, 기록·요약에 userinfo 없음 |
| P3 | `[::1]:443`만 받음. `[::1]`, `::1:443`, zone id, 뒤에 쓰레기 | 400 |
| P4 | 경로·쿼리·#·스킴·`/`·`*` | 400 |
| P5 | `good:443@evil:443` 같은 파서 차이 | 400. 기록한 host = 실제 연결한 host |
| P6 | 공백·탭·NUL·ESC | 400(Node가 먼저 막아도 됨) |
| P7 | 퍼센트 인코딩, 비ASCII | 400 (punycode는 받음) |
| P8 | `LOCALHOST:<자기>`, `localhost.:<자기>`, `2130706433`, `0x7f000001`, `0177.0.0.1`, `127.1` | 숫자 변형은 400, 이름은 해석 후 루프면 508 |
| P9 | 라벨 64자, 전체 254자, 10KB | 400, DNS 조회 없음 |
| P10 | Host ≠ 대상 / Host 중복 | 대상 기준으로 연결·기록 / 400 |

## Q. 허용 범위
| # | 입력 | 기대 | 배정 |
|---|---|---|---|
| Q1 | 자기 포트로: 127.0.0.1, localhost, 127.0.0.2, [::1], [::ffff:127.0.0.1], 0.0.0.0, [::], 127로 풀리는 이름 | 508, 목적지 연결 없음 | 1 |
| Q2·Q3 | 127.0.0.1의 다른 포트, 사설 주소 | 허용(결정 2) | 1 |
| Q4 | 443이 아닌 포트 | 허용(결정 1), 기록에 포트 | 1 |
| Q5 | 이름이 여러 주소(하나가 루프) / 두 번 해석하면 바뀜 | 한 번만 해석, 하나라도 자기면 508, 검사한 주소로 연결, 연결한 주소를 기록 | 1 |
| Q6 | origin-form 본문 안에 CONNECT | 400(회귀) | 1 |

## R. 견고성
| # | 상황 | 기대 | 배정 |
|---|---|---|---|
| R1 | CONNECT와 같은 write로 보낸 데이터(head) | 목적지에 정확히 한 번, 먼저, 바이트 수에 포함 | 1 |
| R2 | CONNECT에 Content-Length / Transfer-Encoding | 400 | 1 |
| R3 | keep-alive로 GET 뒤 CONNECT / CONNECT 뒤 바로 GET 바이트 | 앞 GET 정상, 뒤 바이트는 터널 데이터로만 | 1 |
| R4 | 200 응답 형식 | 상태줄만, CL·TE 없음, 연결 성공 뒤에만 | 1 |
| R5 | 목적지 먼저 끝 / 클라이언트 먼저 끝 / 클라이언트 RST / 연결 전에 클라이언트 끊음 | 반대쪽도 닫힘, 기록 1개, 프로세스 생존 | 1 |
| R6 | half-close | FIN 전달(결정 6) | 1b |
| R7 | 양방향 50~100MB, 느린 클라이언트 | 바이트 동일, 메모리 일정 | 1b |
| R8 | 연결이 끝나지 않는 목적지 | 504(연결 함수 주입 필요) | 1b |
| R9 | 연결 뒤 유휴(연결 타임아웃보다 오래) | 끊지 않음 | 1 |
| R10 | 닫힌 포트, 없는 이름 | 502, 고정 문구, 실패 구분 | 1 |
| R11 | 200 뒤 목적지 RST | 클라이언트를 destroy(정상 종료로 위장하지 않음) | 1 |
| R12 | 동시 터널 300개 | 섞이지 않음 | 1b |
| R13 | 열린 터널이 있는 채로 close() | 정해진 시간 안에 끝남 | 1b |

## S. 기록·출력 (전부 1)
S1 양방향 바이트 수 정확(CONNECT 헤더·200 줄 제외, head 포함) / S2 기록 정확히 1개 / S3 터널 내용이 기록에 없음 / S4 Proxy-Authorization·userinfo가 요약 줄에 없음 / S5 400·508·502·504·클라이언트 중단·200 뒤 리셋이 구분됨 / S6 시간은 단조 시계, 연결한 IP 기록

## T. TLS-4에서 다시 (4)
T1 CA가 있는데 TLS가 아닌 터널 / T2 SNI ≠ CONNECT host(domain fronting) / T3 head의 ClientHello를 TLS 소켓에 / T4 목적지 인증서 검증 기본 켬(TLS-T), IP SAN, 가짜 인증서 캐시 상한 / T5 바이트 수 기준과 Flow 단위, h2·pinning 앱
