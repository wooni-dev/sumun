# PRX-1 보안·경계 사례 (O10: 검토 에이전트 제안)

출처: 2026-11-07, 별도 컨텍스트의 검토 에이전트가 **명세만 보고** 제안 [추측: 코드 없음, 실행 안 함]. 작업자의 구현안은 알려 주지 않았다. 표준 근거는 RFC 9110/9112.
배정: **1** = PRX-1에서 테스트, **1b** = PRX-1b(견고성·경계)에서 테스트, **밖** = 범위 밖.

## A. 열린 프록시 방지
| # | 입력 | 기대 | 배정 |
|---|---|---|---|
| A1 | 기본값으로 시작 | 리스닝 주소가 정확히 127.0.0.1 (0.0.0.0, :: 아님) | 1 |
| A2 | LAN IP로 접속 | 연결 거부 | 1b (환경 의존) |
| A3~A6 | host를 0.0.0.0, ::, LAN IP, localhost, IPv4-mapped로 설정 | 시작 거부 / 루프백만 | **1: host 설정 자체를 제공하지 않는다**(항상 127.0.0.1). 설정이 생기면 1b |
| A7~A9 | 포트 충돌(다른 프로세스, 같은 포트 두 개, 0.0.0.0:8080 점유) | 분명한 오류, 몰래 다른 포트로 안 뜸 | 1b |
| A10 | 포트 0, -1, 65536, abc | 시작 거부 | 1b (CLI 단계) |
| A11 | origin-form `GET /x` + `Host: 127.0.0.1:8080` (웹페이지 fetch) | 400, Host를 목적지로 쓰지 않음 | 1 |
| A12 | origin-form + `Host: evil.example:8080` (DNS 리바인딩) | 400 | 1 |

## B. 루프와 견고성
| # | 입력 | 기대 | 배정 |
|---|---|---|---|
| B1 | `GET http://127.0.0.1:<프록시 포트>/` | 508, 바깥 연결 없음 | 1 |
| B2 | localhost, [::1], 127.1, 0x7f000001, 0.0.0.0, 127.0.0.2 등 다른 표기 | 508(또는 자기에게 닿지 않으면 502). 무한 반복 없음 | 1: localhost, [::1]. 나머지 1b |
| B3 | 127.0.0.1로 풀리는 호스트명 | B4(Via)로 잡힘 | 1b |
| B4 | 요청에 이 프록시의 Via 식별자가 이미 있음 | 508 | 1 |
| B5 | 포트를 바꿔도 루프 감지 | 하드코딩 아님 | 1 (테스트는 임의 포트를 씀) |
| B6 | HTTP_PROXY 환경변수가 이 프록시를 가리킴 | 바깥 연결은 환경변수를 무시 | 1b |
| B7 | 목적지·클라이언트가 중간에 끊음 | 프로세스가 죽지 않음, 잘린 응답을 완전한 것처럼 넘기지 않음 | 1b |
| B8 | 목적지가 응답하지 않음 | 504 | 1b |
| B9 | 1GB 업로드·다운로드 | 메모리 일정(스트리밍), 바이트 동일 | 1b |
| B10 | 없는 도메인, 닫힌 포트 | 502 | 1: 닫힌 포트. 없는 도메인은 1b(DNS 의존) |
| B11 | 깨진 목적지 응답(CL+TE 등) | 502 | 1b |
| B12 | 오류를 일으키는 URL에 `<script>` | 오류 응답은 text/plain, 입력을 반영하지 않음, 경로나 스택 트레이스 없음 | 1 |

## C. 잘못된 URL과 Host
| # | 입력 | 기대 | 배정 |
|---|---|---|---|
| C1 | `GET *`, `OPTIONS *` | 400 | 1b |
| C2 | 호스트 없는 URL | 400 | 1b |
| C3 | ftp://, file:///C:/Windows/win.ini, gopher:// | 400 | 1 |
| C4 | absolute-form `GET https://...` | 501 (평문 다운그레이드 금지) | 1 |
| C5~C7 | 이상한 포트, userinfo, 요청줄 제어문자 | 400 / userinfo 제거 | 1b |
| C8 | `#frag` | 넘기는 요청줄에서 제거 | 1 |
| C9 | `%2F`, `..` | 정규화하지 않고 그대로 | 1b |
| C10 | 경로 없음 `http://h` | `/`로 넘김 | 1 |
| C11~C13 | IPv6 리터럴, 대소문자, 100KB URL | — | 1b |
| C14 | `GET http://a/` + `Host: b` | Host를 a로 바꿔 넘김 (RFC 9112 3.2.2 MUST) | 1 |
| C15~C17 | Host 없음 / 여러 개 / HTTP/1.0 | 400 / 400 / 정상 | 1b |
| C18 | CONNECT | 501, 바깥 연결 없음, 멈추지 않음 | 1 |
| C19 | PUT, DELETE, PATCH + 본문 | 그대로 넘김 | 1: POST 본문. 나머지 1b |

## D. 요청 스머글링·큰 헤더 (전부 1b)
D1 CL+TE 함께 → 400 / D2 다른 CL 두 개 → 400 / D3 CL 값 이상 → 400 / D4 TE 난독화 → 400 / D5 HTTP/1.0 + TE / D6 헤더 이름 뒤 공백 → 400 / D7 obs-fold → 400 / D8 CR·LF 단독, NUL → 400 / D9 잘못된 chunk / D10 파이프라인 경계 / D11 Expect: 100-continue / D12 HEAD·204·304 응답 경계 / D13 연결 종료로 끝나는 응답 / D14 64KB 헤더 → 431 / D15 헤더 5,000개 → 431 / D16 응답 헤더 초과 → 502 / D17 느린 헤더 → 408

## E. hop-by-hop
| # | 입력 | 기대 | 배정 |
|---|---|---|---|
| E1 | Connection, Proxy-Connection, Keep-Alive, TE, Trailer, Upgrade, Proxy-Authorization | 목적지에 하나도 전달 안 됨 | 1 |
| E2 | Proxy-Authorization | 절대 전달 안 됨 | 1 (E1에 포함) |
| E3 | `Connection: keep-alive, X-Secret` + X-Secret | X-Secret 제거 | 1 |
| E4 | 소문자, 빈 토큰, 여러 줄 | 모두 합쳐 제거 | 1b |
| E5 | `Connection: Host, Content-Length` | Host 항상 있음, 본문 경계 일치 | 1 |
| E6 | `Connection: Cookie, Authorization` | 정책을 정해 고정 → **RFC대로 제거** (Claude 추천, 결정 항목) | 1b |
| E7 | Upgrade websocket / h2c | 넘기지 않음, 101이면 502 | 1b |
| E8 | 응답의 `Connection: X-Foo` + X-Foo | 클라이언트에 전달 안 됨 | 1 |
| E9~E12 | 응답 chunked 경계, Connection: close 독립성, keep-alive로 다른 목적지, Set-Cookie 여러 줄 | — | 1b |
| E13 | 일반 요청 | 요청·응답에 `Via: 1.1 sumun`, 기존 Via 보존 (RFC 9110 7.6.3 MUST) | 1 |
| E14 | 일반 요청 | X-Forwarded-For, Forwarded를 추가하지 않음 | 1b |

## 범위 밖 (검토자 판단, 13개)
같은 PC의 다른 계정, 프록시 인증, 프록시를 통한 localhost 서비스 접근(SSRF), origin-form 거부 외의 DNS 리바인딩 대응(→ 대시보드 단계에서 다시 봄), 의도적 DoS, HTTPS 관련, 캐시, 기록의 개인정보(→ PRX-2), HTTP/2·3, TRACE, 속도 제한, DNS 스푸핑, 리다이렉트 루프.

## 결정 항목 (검토자가 남김)
- 루프 응답 코드: **508 Loop Detected** (Claude 추천. RFC 5842에서 정의했고, 프록시 루프 표시로 널리 쓰임)
- E6: Connection에 나열된 인증 헤더 → **RFC대로 제거**. 단 Host, Content-Length는 지우지 않음(E5)

## 배정 갱신 (2026-11-07, PRX-1b 시작 시)
"1b"를 둘로 나눈다. 사례가 겹치면 더 이른 단위로 본다(PRX-1 감사 관찰 O28).
- **1b (요청 쪽)**: C1, C2, C5, C6, C7, C9, C11(zone ID만), C12, C13, C15, C16, C17, C19(PUT·DELETE·PATCH), D1~D10, D14, D15, E4, E6, E14
- **1c (목적지 쪽·견고성·설정)**: A2, A7~A10, B2(나머지 표기), B3, B6, B7, B8, B9, B10(없는 도메인), B11, C11(IPv6 목적지 연결), D11, D12, D13, D16, D17, E7, E9~E12
- (PRX-1c 시작 시) A10(포트 0, -1, 65536, abc 거부)은 사용자 설정 검사라 **CLI 단계**로 옮긴다. startProxy는 테스트에서 임의 포트(0)를 써야 한다.
